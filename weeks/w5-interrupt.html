CPU 안에서 일어나는 일

USER_SW0(PTB26)를 누르면 SIUL2 EIRQ[13] → NVIC → 스택 → ISR → 복귀 순서로 흘러가요. 하나씩 눌러 보면서 따라가요.

01폴링 vs 인터럽트

폴링은 CPU가 루프를 돌며 "눌렸나?"를 계속 확인하는 방식이에요. 루프 안에 LCD 출력처럼 긴 작업이 있으면, 그 작업이 끝나야 다음 확인을 해요. 버튼을 시간 23에 누르면 각각 언제 알아챌까요? 숫자를 끌어 보세요.

시간 → 시간 단위는 설명용

핵심은 "CPU가 기다리는 게 아니라, 하드웨어가 CPU를 부른다"예요. 대신 ISR이 언제 끼어들지 모르기 때문에(비동기), main과 같이 쓰는 변수는 조심해서 다뤄야 해요.

02Cortex-M7 벡터 테이블

벡터 테이블은 "예외 번호 → 처리 함수 주소"를 적어 둔 표예요. 0~15번은 ARM 코어 내부 예외, 16번부터가 칩 제조사(NXP)가 만든 외부 인터럽트(IRQ 0~)예요.

벡터주소 오프셋내용
00x0000_0000초기 스택 포인터 (Initial MSP)
10x0000_0004Reset 핸들러
20x0000_0008NMI
30x0000_000CHardFault: 잘못된 주소 역참조, 정렬 오류 등에서 여기로 점프
4~0x0010~MemManage, BusFault, SysTick …
16~0x0040~외부 인터럽트 (NVIC IRQ 0~). SIUL_1_IRQn = IRQ 54도 여기
시험 단골"HardFault에 멈췄다"면 잘못된 메모리 접근 같은 치명적 오류로 벡터 3에 들어간 거예요. 이때 하드웨어가 자동 PUSH한 스택 프레임의 PC 값을 보면 문제를 일으킨 코드 줄을 찾을 수 있어요.

03EIRQ 32개 → NVIC 벡터 4개

S32K312의 외부 인터럽트 라인 EIRQ[0]~[31]은 각자 벡터를 갖지 않고, 8개씩 묶여서 NVIC 벡터 4개(IRQ 53~56)를 같이 써요. EIRQ[13]은 어느 묶음일까요? 숫자를 끌어 보세요. 실습 버튼 PTB26은 EIRQ[13]이에요.

낚시 2PTB26 버튼에 SIUL_0_IRQn을 고르면 안 돼요. EIRQ 13은 8~15 그룹이라 반드시 SIUL_1_IRQn(IRQ 54)과 SIUL2_EXT_IRQ_8_15_ISR이에요. 틀리면 벡터 자체가 안 불려요.

04인터럽트 한 번, 처음부터 끝까지

실습 코드를 줄여서 가져왔어요. 아래 버튼으로 MCAL 프로젝트와 IPL 프로젝트를 번갈아 볼 수 있어요. 수업 실습은 주로 MCAL로 진행해요. → 를 누르면 main 루프를 돌다가 버튼이 눌리고, 스택에 레지스터가 쌓이고, 콜백이 실행되고, 원래 자리로 돌아와요.

05Tail-chaining (꼬리 물기)

ISR A가 끝날 때 ISR B가 이미 기다리고(pending) 있으면, 스택을 POP했다가 바로 다시 PUSH하는 건 낭비예요(약 30 클럭). Cortex-M은 이 둘을 건너뛰고 바로 ISR B로 들어가요.

우선순위는 숫자가 작을수록 높아요(0이 최고). 실습은 버튼에 10을 줬어요. 그래서 더 급한 인터럽트(예: 0~5)는 버튼 ISR을 선점(Preemption)할 수 있어요.

06ISR 3대 원칙

  1. Fast Exit: ISR은 수 µs 안에 끝내요. 실행되는 동안 같거나 낮은 우선순위 인터럽트가 모두 막혀요.
  2. 무거운 일은 main으로: LCD 출력(Lcd1602_Puts)은 I2C로 수십 바이트를 보내는 블로킹 작업이라 수 ms가 걸려요. printf, 딜레이도 금지예요.
  3. 공유 변수는 volatile: 빠지면 컴파일러가 main 루프에서 값을 레지스터에 캐싱해서, ISR이 바꿔도 영원히 못 알아채요.

좋은 ISR: 알림만 남기고 즉시 복귀

void UserSw0_Callback(void)
{
    g_press_count++;
    g_led_request ^= 1U;
}

나쁜 ISR: 시스템 전체가 멈춤

void UserSw0_Callback(void)
{
    Lcd1602_Puts("Count: 1");  // I2C 블로킹
    printf("Pressed\n");       // 느림
    Delay(1000);               // 금지
}
낚시 1ISR 안에서 LCD 출력이나 printf를 해도 된다? 0점이에요. ISR은 카운트 증가와 플래그 토글만 하고, 출력은 main 루프가 맡아요.

07채터링과 디바운싱

기계식 버튼은 한 번 누를 때 금속 접점이 1~10ms 동안 튀면서 붙었다 떨어지기를 반복해요. 에지 인터럽트는 상승 에지마다 ISR을 부르니까, 한 번 눌렀는데 카운트가 여러 번 올라가요. 디바운싱은 "직전 이벤트와 너무 가까우면 무시"하는 방법이에요. 무시 구간을 0 ms로 하면 몇 번 셀까요?

PTB26 입력 파형 (버튼 2번 누름) 예시 파형

void UserSw0_Callback(void)
{
    static uint32_t last_tick = 0U;
    uint32_t now = GetSystemTick();
    if ((now - last_tick) < DEBOUNCE_TICKS)
    {
        return;  // 너무 가까움 = 접점 튐, 무시
    }
    last_tick = now;
    g_press_count++;
    g_led_request ^= 1U;
}

08IPL vs MCAL: 같은 일, 다른 API

두 방식은 서로 대체 관계라서 한 프로젝트에서 섞으면 안 돼요. MCAL 프로젝트에서는 Siul2_*_Ip를 쓰지 않고, 하드웨어 번호 대신 기호 이름을 써요.
