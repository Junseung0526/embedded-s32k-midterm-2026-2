SIUL2의 MSCR과 GPDO 레지스터를 직접 주소로 건드려서 D13 빨간 LED(PTA29)를 켜요. 드라이버가 대신해 주던 일을 맨손으로 해 보는 주차예요.

01같은 문장, 다른 결과: Memory-Mapped I/O

MCU에서는 RAM, Flash, 주변장치 레지스터가 하나의 주소 공간에 놓여 있어요. 그래서 *ptr = 1U;라는 똑같은 문장도 ptr이 어디를 가리키느냐에 따라 결과가 완전히 달라요.

*ptr = 1U;
SRAM의 counter0
보드 D13 (PTA29)꺼짐

그래서 volatile컴파일러 눈에는 레지스터도 그냥 변수처럼 보여요. "값이 안 바뀌네" 하고 쓰기나 읽기를 지워 버리면, 코드는 멀쩡한데 보드는 안 움직여요. 그래서 레지스터 주소는 항상 (*(volatile uint32_t *)주소)로 감싸요. 자세한 건 힌트 페이지 05에 있어요.

02SIUL2: 핀을 담당하는 주변장치

SIUL2(System Integration Unit Lite2)는 핀 기능 선택과 GPIO 입출력을 맡아요. 레지스터가 여섯 종류 있는데, 이번 주는 MSCR과 GPDO 두 개만 써요.

레지스터이름하는 일
MSCR[n]Multiplexed Signal Configuration핀 기능, 출력·입력 버퍼, 전기적 속성 설정
IMCR[n]Input Multiplexed Signal Configuration주변장치 입력 신호가 어느 pad에서 올지 선택
GPDO[n]GPIO Pad Data OutputGPIO 출력 값 쓰기
GPDI[n]GPIO Pad Data InputGPIO 입력 값 읽기
PGPDO[n]Parallel GPIO Pad Data Output여러 GPIO 출력을 한 번에 쓰기
PGPDI[n]Parallel GPIO Pad Data Input여러 GPIO 입력을 한 번에 읽기

03MSCR: 이 핀을 "GPIO 출력"으로

MSCR은 핀마다 하나씩 있는 32비트 설정 레지스터예요. 이번에 볼 필드는 두 개예요. OBE(비트 21, Output Buffer Enable)를 1로 켜고, SSS(비트 3:0, Source Signal Select)를 GPIO 기능인 0으로 맞춰요. 비트를 직접 눌러 보세요.

MSCR[n]의 주소

MSCR은 32비트(4바이트) 배열이라 계산이 단순해요. MSCR[n] = 0x40290000 + 0x0240 + 4 × n. 빨간 숫자를 끌어 보세요: MSCR[29]

읽기-수정-쓰기: GpioBare_SetOutput()

다른 비트는 건드리지 않고 필요한 필드만 바꾸려면, 레지스터를 읽어서 → 지역 변수에서 고치고 → 다시 써요. 오른쪽 위가 지역 변수 value, 아래가 실제 레지스터 MSCR[29]예요.

04GPDO는 4개씩 거꾸로 놓여 있다

GPDO는 GPIO 하나당 1바이트예요. 그런데 4바이트 묶음 안에서 순서가 뒤집혀 있어요. 0x1300 칸에 GPDO0이 아니라 GPDO3이 있어요. 숫자를 끌어서 GPIO 번호를 바꿔 보세요: GPIO[29]

진짜 GPDO 칸0x1300 + n으로 잘못 계산한 칸

3초 암산법① n보다 작거나 같은 가장 가까운 4의 배수를 구해요. ② 4로 나눈 나머지 R을 구해요. ③ 더할 바이트 = (4의 배수) + (3 − R). GPIO[29]면 28 + (3 − 1) = 30 = 0x1E라서 0x131E예요.
낚시MSCR 번호와 GPIO 번호는 다른 레지스터의 인덱스예요. PTA29는 우연히 둘 다 29지만, 항상 IOMUX 표에서 따로따로 확인해요.

05chap02_gpio_bare를 한 줄씩

USE_SDK_HEADER_ACCESS = 0(직접 주소 매크로)일 때의 흐름이에요. 함수 안으로 들어가는 줄은 매크로가 실제로 어느 주소에 쓰는지까지 보여 줘요.

왜 처음에 Off부터 쓸까LedInit()이 출력으로 바꾸자마자 Off 레벨을 쓰는 건, 전원을 켠 직후 핀이 떠 있거나 남은 전압 때문에 LED가 잠깐 깜빡이는 글리치를 막기 위해서예요.

06직접 주소 vs SDK 헤더

USE_SDK_HEADER_ACCESS를 1로 바꾸면 같은 일을 IP_SIUL2 구조체로 해요. 결과(LED 점멸)는 똑같아요.

직접 주소 매크로 (0)

GpioBare_SetOutput(LED_RED_MSCR_INDEX);
GpioBare_Write(LED_RED_GPDO_INDEX, level);
// 속: *(volatile uint8_t *)0x4029131E = level;

SDK 헤더 구조체 (1)

IP_SIUL2->MSCR[29] = value;
IP_SIUL2->GPDO29   = level;
// 주소 계산은 헤더가 대신
비교직접 주소 매크로SDK 헤더
주소 계산 이해높음낮음
코드 가독성낮음높음
오타 위험높음낮음
이식성낮음높음
목적레지스터 구조 이해 (학습)실무형 접근

실무에서는 SDK 헤더나 드라이버를 먼저 써요. 그래도 한 번은 맨손으로 해 보는 이유는, 하드웨어가 결국 주소와 비트 필드로 움직인다는 걸 알아야 HAL·MCAL·RTD가 무엇을 대신해 주는지 보이기 때문이에요.

Config Tools도 클럭 API도 안 썼는데 GPIO가 움직이는 이유: S32DS 기본 startup 코드가 최소한의 시스템/버스 클럭을 미리 켜 두기 때문이에요.

07핀 정보는 세 문서를 차례로

"D13 LED는 어느 주소?"의 답은 한 문서에 다 있지 않아요. 숫자는 추측하지 말고 문서에서 직접 확인해요.

1보드 매뉴얼p.19 User LED Indicators

D13 = RGBLED0_RED = PTA29, Active High

2IOMUX 표PTA29 행

SIUL_MSCR29, GPIO[29]

3RTD 헤더S32K312_SIUL2.h

base 0x40290000, MSCR +0x240, GPDO29 +0x131E

Active High라서 1을 쓰면 켜지고 0을 쓰면 꺼져요. Active Low라면 반대예요. LED가 초록이나 파랑으로 켜지면 GPDO 번호를 잘못 계산했을 가능성이 커요.
