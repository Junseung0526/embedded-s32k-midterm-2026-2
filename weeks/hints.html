교수님이 "꼭 나온다"고 하신 네 가지예요. 숫자를 바꾸고, 비트를 눌러 보고, 코드를 한 줄씩 넘기면서 손으로 익혀요.

01비트 연산자 6종

A, B 칸에 16진수를 넣거나 비트 칸을 직접 눌러 보세요. 위 연산 버튼을 바꾸면 결과 줄이 다시 계산돼요. 기본값은 노션 예제와 같은 A = 0x4B, B = 0x36이에요.

결과

낚시 1&와 &&는 달라요. 비트 연산 1 & 2는 0001과 0010을 칸마다 AND해서 0, 논리 연산 1 && 2는 "둘 다 참이냐"라서 1이에요.
낚시 2==와 +가 비트 연산자보다 먼저 계산돼요. 조건식은 항상 ((REG & (1U << n)) != 0)처럼 괄호로 감싸요.
낚시 3시프트에는 1U(unsigned)를 써요. 음수를 >>하면 빈자리에 0이 아니라 부호 비트 1이 채워져요. 위 체크박스를 켜고 A를 B4로 바꿔 보면 바로 보여요.

02레지스터 마스킹 4공식

SET은 OR, CLEAR는 AND + NOT, TOGGLE은 XOR, CHECK는 AND예요. 항상 (1U << n)으로 "n번 칸만 1인 마스크"를 먼저 만들어요. 오른쪽 MASK 줄이 그 마스크예요.

03주소에 직접 접근: *((int *)0x10002000)

일반 프로그램은 변수 주소를 컴파일러가 정하지만, MCU 레지스터는 데이터시트에 적힌 고정 주소에 있어요. 그 주소로 바로 찾아가는 식을 안쪽부터 네 단계로 쪼개 볼게요.

낚시*( (int *)0x10002000 )에서 괄호를 빼면 안 돼요. 숫자를 먼저 (int *)로 주소로 바꾸고, 그 다음에 맨 앞 *로 찾아가요.

04구조체로 레지스터 묶기 & 4바이트 오프셋

연속된 레지스터를 구조체로 묶고 베이스 주소로 캐스팅하면, ->만 써도 컴파일러가 오프셋을 계산해 줘요. 32비트 레지스터는 4바이트라서 주소가 +4씩 늘어나요.

숫자를 좌우로 끌어 보세요. msrstart->v3의 주소는 어떻게 계산될까요?

오프셋 계산기: 몇 번째 멤버?

낚시 (제일 많이 틀림)세 번째 칸 v3은 +12바이트인데, 12는 16진수로 0x0C예요. 그래서 주소는 0x1000200C예요. 0x10002012라고 쓰면 감점이에요. v4도 +16 = 0x10이라서 0x10002010이에요.
낚시포인터에는 ->를 써요. msrstart->v0는 (*msrstart).v0와 같고, msrstart.v0는 컴파일 에러예요.

05volatile이 없으면 생기는 일

컴파일러는 루프 안에서 값이 안 바뀌는 것처럼 보이면, 메모리에 매번 가지 않고 CPU 레지스터에 복사해 둔 값을 재사용해요. 그런데 하드웨어나 ISR은 코드와 상관없이 메모리 값을 바꿔요. 아래 버튼으로 ISR이 flag를 1로 바꿔 보세요.

int flag; // volatile 없음

while (flag == 0) { }
메모리 flag0
CPU 레지스터 사본0

루프 도는 중

volatile int flag;

while (flag == 0) { }
메모리 flag0
CPU가 읽은 값0

루프 도는 중

그래서 MCAL과 SDK 헤더는 레지스터 주소를 항상 volatile로 정의해요.

#define REG_MSR0  (*( (volatile uint32_t *)0x10002000 ))
#define REG_MSR1  (*( (volatile uint32_t *)0x10002004 ))
