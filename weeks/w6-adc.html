가변저항을 돌렸을 때
숫자가 LCD에 뜨기까지

ADC_POT0(PTA11)의 전압이 ADC1_S10을 거쳐 정수 코드가 되고, 하드웨어 평균과 이동 평균을 지나 LCD에 HW · MA · 전압으로 찍혀요. 하나씩 만져 보면서 따라가요.

01양자화와 분해능

ADC는 연속적인 전압을 정수 코드로 바꿔요. 12-bit면 이상적으로 0~4095이고, V = code × Vref / 4095예요. 분해능을 12-bit로 두면 코드는 몇 단계까지 있고 1 LSB는 얼마일까요? 숫자를 끌어 보세요. (Vref는 교재 예제대로 5000 mV)

해석의 출발점ADC 값은 "정확한 전압"이 아니라 센서·회로·기준전압·샘플링 조건의 결과예요. 기준전압 오차, 입력 노이즈, 샘플 시간, 회로 임피던스가 모두 값에 섞여 있어요.

02SAR ADC: 비트를 위에서부터 하나씩

입력 전압을 샘플-홀드로 잠시 잡아 두고, 내부 DAC와 비교기로 가장 높은 비트부터 하나씩 결정해요. 비트를 켜 본 값(DAC 출력)이 입력보다 크면 그 비트는 0, 아니면 1로 남겨요. 입력이 2400 코드일 때 비트가 어떻게 정해질까요? 지금 단계를 끌어 보세요: 0 / 12

입력 임피던스가 높거나 샘플 시간이 짧으면 샘플 커패시터가 충분히 충전되지 않아 값이 흔들려요. ADC가 이상하면 코드만 보지 말고 입력 핀 매핑, 기준전압, 입력 신호 범위, 샘플링 주기, 전원·GND 노이즈를 같이 봐요.

03가변저항에서 ADC1_S10까지

보드 내장 가변저항(R393, 10 kΩ)은 PTA11(160번 핀)에 연결돼요. 노브 위치가 전압(0 ~ VDD_HV_A_PERH)이 되고, 이 핀이 ADC1의 채널 S10이에요. 채널은 내가 고르는 게 아니라 핀이 정해요. 노브 50%에서 ADC 인스턴스를 바꿔 보세요.

읽을 ADC

자주 틀리는 곳온보드 가변저항은 ADC1 채널 10으로 읽어요. ADC0이 아니에요. MCAL 설정에서는 같은 채널이 S10_ChanNum34(Channel Id 34)로 나오고, 두 곳의 번호를 똑같이 맞춰야 해요.

04하드웨어 평균과 이동 평균

이번 실습은 평균을 두 번 써요. ADC가 한 번 변환할 때 같은 채널을 8번 연속 변환해 평균 하나를 내고(MCR[AVGEN]=1, MCR[AVGS]), 소프트웨어가 그 결과를 최근 8번 모아 한 번 더 평균을 내요.

노브를 갑자기 돌린 상황을 시뮬레이션했어요. 노이즈 30 LSB, 이동 평균 창 N=8로 해 보세요. 두 슬라이더를 움직이면 안정성과 응답 속도가 서로 바꿔치기되는 게 보여요.

읽기 횟수 → 예시 신호 (노브를 12번째 읽기에서 돌림)

두 평균이 겹치면 filtered 하나에는 8 × 8 = 64회 변환이 같은 비중으로 들어가요. 값은 더 안정되지만, 가변저항을 돌리면 filtered가 새 값을 다 따라가는 데 8번을 더 읽어야 해요. 하드웨어 평균도 공짜가 아니라서 평균 횟수만큼 변환 시간이 늘어요. 가변저항처럼 느린 신호는 괜찮지만 모터 전류 같은 빠른 신호는 신중히 정해요.

적용 범위하드웨어 평균 설정(MCR)은 ADC 인스턴스마다 하나라서 그 ADC의 모든 채널에 같은 평균이 적용돼요. 보정(calibration)용 평균은 별개이고, Adc_Sar_Ip_DoCalibration()이 32회로 직접 설정해요.

05adc_filter.c 한 줄씩

이동 평균은 매번 N개를 다시 더하지 않아요. 합(sum)을 들고 있다가 "가장 오래된 값을 빼고 새 값을 더해서" 갱신해요. 그림에서는 칸을 4개로 줄였어요(칸). → 를 눌러 같은 입력이 다섯 번 들어오는 과정을 따라가요.

count의 역할처음엔 버퍼가 0으로 차 있어요. count 없이 항상 N으로 나누면 시작 직후 표시값이 작게 나와요. 그래서 다 차기 전에는 채운 개수로 나눠요. AdcFilter_Init()은 루프에 들어가기 전에 한 번만 불러요.

06설정 함정: 기본 분해능은 14-bit

Config Tools의 Conversion resolution 기본값은 14-bit예요. 바꾸지 않으면 코드는 0~16383이 되는데, 식은 그대로 mv = filtered × 5000 / 4095라서 전압이 약 4배로 찍혀요. 노브를 50%에 두고 설정을 바꿔 보세요.

Conversion resolution

결과 레지스터 PCDRn[CDATA]는 15비트 폭이고, MCR[WLSIDE]=0(우측 정렬)이면 bits [14:0]에 값이 들어와요. 분해능은 CALBISTREG[RESN]에서 14·12·10·8-bit 중 골라요. Adc_Sar_Ip_Init()이 이 값들을 레지스터에 써 넣어요.

Vref도 확인교재 계산 예제는 5000 mV를 기준으로 하지만, 실제 Vref는 보드 설정과 전원 상태에 따라 달라요. 보고서에는 실제 설정이나 측정값을 적어요.

07IPL vs MCAL: 같은 읽기, 다른 길

실습 A(IPL)는 Adc_Sar_Ip를 직접 쓰고 완료 flag를 폴링해요. 그래서 ADC 인터럽트와 notification은 필요 없어요. 실습 B(MCAL)는 group을 만들고 완료를 콜백으로 받아요. 두 방식은 섞지 않아요. MCAL의 AdcGroup_POT나 Adc_* API를 IPL 프로젝트에 넣으면 안 돼요.

{
    AdcConvDone = TRUE;
}

나쁜 콜백: ISR에서 LCD 출력

void Adc1_Callback(void)
{
    Lcd1602_Puts("HW:1234");  // I2C 블로킹

}
5주차와 같은 규칙콜백은 ISR 안에서 실행돼요. 플래그만 세우고 끝내고, main과 같이 쓰는 변수는 volatile로 선언해요. 빠지면 콜백은 불리는데 main이 영원히 대기해요.
